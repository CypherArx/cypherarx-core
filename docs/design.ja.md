## 目的

CypherArx はよくある「サイト、ユーザー名、パスワード」の一覧では持てないデータのための
パスワードマネージャーです。すべてを手元の 1 つのファイルに持ち、どこにも送りません。

次の 3 つがそろっていることが、存在する理由です。ほかのことはここから導かれます。

- 階層を持てること。サービスはアカウントを持ち、アカウントはその下にカード、トークン、
  バックアップコードなどを持ちます。
- フィールドを自由に作れること。エントリはラベルの付いた値をいくつでも持ちます。複数の
  パスワード、暗証番号、登録した電話番号、ワンタイムパスワードの秘密、リカバリーコードなどです。
- サービスをまたいで複数の名義を扱えること。人は複数の名義で活動し、同じサービスにそれぞれの
  アカウントを持つことがあります。アカウントはサービスごとにも名義ごとにも見られます。
  どちらの表示に出るのもコピーではなく同じアカウントです。

どうログインするかも記録します。パスワードでログインするのか、別のアカウントを経由するのか
（「〜でログイン」）です。

## 構造

```
cypherarx-core    ライブラリ：暗号、保存、モデル、生成、ワンタイムパスワード、インポート
      ▲
cypherarx-gui     アプリケーション：画面、セッションとロック、クリップボード、OS との連携
```

- ロジックはコアにあり、ほかの場所にはありません。コアは C++23 のライブラリで、画面を持たず、
  画面のことを知りません。その上のアプリケーションはコアの API を呼ぶだけで、コアが持つべき
  ものを足しません。
- コマンドラインのツールは意図して作っていません。保存したパスワードを出力するコマンドは、
  持ち主にとって便利なのと同じだけ、同じコンピューターで動くほかのソフトウェアにとっても
  便利だからです。
- コアはネットワークに接続しません。コアの中に、金庫をどこかへ送れるものはありません。
- コアが依存するのは、libsodium（暗号のすべて）、SQLite（ファイル）、zxcvbn-c（パスワードの強度の
  推定）、miniz（インポートの形式の 1 つの展開）です。

コアは次の部分からできています。

| 部分 | 役割 |
|---|---|
| `Secret`、`crypto`、`kdf`、`vault_key` | 保護メモリ、暗号化、鍵の導出、2 層の鍵 |
| `Vault` | ファイル。作成、オープン、形式のバージョン、エントリ、フィールド、ログイン方法、カテゴリ、タグ、設定、アクセス記録、鍵のローテーション |
| `passgen`、`totp`、`strength` | パスワードの生成、ワンタイムパスワード、マスターパスワードの判定 |
| `import`、`erase` | ほかの製品がエクスポートしたファイルの読み取り、ファイルの上書きと削除 |

呼び出し側が扱うべき失敗は、例外で投げず、値として返します（`std::expected`）。パスワードの
誤りや復号できない値は、例外的な事態ではなく、結果の 1 つだからです。

アプリケーションの `cypherarx-gui` も同じ考えで分けてあります。`model` は描画以外のすべてを
受け持ちます（何が選ばれているか、2 つの表示に何が入るか、いつロックするか、いつクリップ
ボードを消すか）。`model` はウィンドウなしでテストします。画面はモデルを描くだけです。OS ごとに
違うものは小さな `platform` の部分にまとめてあります。今は Windows で動きます。

## 原則

判断に迷ったときは、これで決めます。

1. 安全を犠牲にして、実装が楽をしてはいけない。
2. ネットワークは最小限に、利用者の意思と一致するときにだけ使う。今は使うことがありません。
3. 持てない責任は持たず、事実を並べる。ソフトウェアは確かめたことを述べます。何かを
   「安全だ」と判定することはしません。
4. 攻撃者にできることを制限する、具体的な対策を考える。「増やせば安全」は落とし穴で、
   具体的な制限のほうが勝ります。
5. 持たなくてよいものは持たず、消すべきものは確実に消す。
6. 見せるものは意味を正確に伝える。
7. OS や確立したライブラリのほうがうまくやれることは、そちらに任せる。メモリのロックも
   暗号のすべても、このプロジェクトで実装したものではなく、libsodium のものです。
8. 新しい機能が別のところを弱めていないかを問う。パスワードのヒントも、文字の種類の
   規則もありません。どちらもパスワードを推測しやすくするからです。
9. 便利な機能は攻撃者にとっても便利である。コマンドラインのツールが無いのは、このためです。
10. 作者自身が使わない機能は作らない。

隠すことで守っているものはありません。ファイルの構造もコードも公開されていて、守っているのは
鍵です。

## 無いもの

思い込みを防ぐために書いておきます。デバイス間の同期、エクスポート、ブラウザとの連携、スマートフォンの
アプリケーション、忘れたマスターパスワードの復旧、第三者による監査は、ありません。
